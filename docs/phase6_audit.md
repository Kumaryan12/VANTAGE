# Phase 6 audit and implementation protocol

Audited 2026-10-28 from clean commit `7cd3fe24af0ba89e18dbf05b1b8b4ffe38d6ad50`, migration head 0008. The supplied Phase 6 brief authorizes extending the previous single-process/session boundary; financial conventions and historical measured reports remain unchanged.

## Executed baseline

The current suite passed **228 backend tests** (two existing dependency deprecation warnings), frontend lint, TypeScript and production build, and **all twelve Chrome workflows**. Logs are ignored under `artifacts/phase6`. PostgreSQL/golden smokes require the local Docker daemon, initially stopped; they will be executed after starting it. Historical CI success is not a substitute for the Phase 6 checks. Full image builds, restart recovery and restore are unverified at this audit stage.

## Reuse and trust boundaries

- Preserve `app/risk`, `app/ml` financial/research definitions and `app/optimization` formulations, independent verification and hash-aware reproduction. Risk/ML/optimization model versions and original reports must not be relabeled by infrastructure work.
- Thin FastAPI routes depend on `BrowserSession`; `owner(session)` currently SHA-256 hashes the opaque session ID. All root resources use a 64-character owner key, child access is scoped through their parent. Explicit owner checks already cover datasets, snapshots/artifacts, models/checkpoints, documents/chunks, investigations/evidence and optimization/governance.
- `auth/sessions.py` keeps 12-hour sessions, Kite tokens and OAuth state in a locked Python dictionary. Restart/expiry loses access even while private records persist. The cookie is HttpOnly/SameSite=Lax with configurable Secure, but has no durable account, revocation registry, RBAC or recovery.
- Request middleware rejects cross-site mutations, redacts validation inputs, disables upstream URL logging and logs only method/path/status/generated request ID/timing. Most responses are no-store. Production configuration, proxy/origin and global limits need explicit validation.
- ML, documents, investigations, evaluations and optimization each have an in-process executor/semaphore and futures. Runner-ID mismatch can incorrectly classify another process's active job as interrupted. Cancellation and most limits are process-local. Reuse their validated input capture and numerical execution, replacing dispatch/publication coordination rather than financial code.
- Approved history/snapshots/compact outputs persist in SQL. ML text/JSON checkpoints and original PDFs persist in separate private filesystem roots, with checksums and contained server-generated paths. DB alone cannot restore all evidence. No private files belong under Next public. Safe deletion must reconcile children, files, indexes and queued work.
- PDFs already have byte/page/text/decompression/CPU/address-space/time limits and a subprocess with stripped environment. It still shares host filesystem/network privileges; stronger isolation is needed. Prompt injection cannot grant tool capabilities; final facts/citations remain deterministically verified.
- Governance is owner-session human research review, not independent reviewer identity. Preserve eight assessments, evidence/reproduction gates, audit lineage and research-only scope while adding assigned reviewer permissions and separation of duties. Platform administration must not confer financial-data access.
- Dockerfiles are non-root but backend startup runs migrations in each API process. Compose uses fallback development secrets, local published ports, separate artifact volumes and no durable broker/worker/proxy. Next's backend rewrite is set at build time. CI tests PostgreSQL and browser paths but does not yet build the complete stack or validate restores/scanners.

## Durable ownership and migration decision

Use local Argon2id passwords through maintained `pwdlib`, opaque high-entropy random browser sessions with only token hashes stored in SQL, explicit expiry/revocation/rotation, generic authentication failures and database-backed throttles. Administration is explicitly provisioned; public registration never grants privileged roles. Password recovery uses expiring single-use operator-issued recovery tokens and documented delivery, without returning or logging secrets through public endpoints. An external OIDC provider can be a later alternative, not a mandatory paid dependency.

Introduce users, persistent sessions, roles/assignments, security events and **ownership scopes**. Retain existing owner keys as immutable workspace IDs. A scope can be bound to one durable user, with user/session foreign keys and explicit active-workspace selection. This avoids rewriting financial payloads, source IDs, artifact paths and reproduction hashes, and avoids deduplication collisions when an account already has new and legacy records. Migration 0009 will backfill existing owner scopes without assigning users. New accounts get a fresh scope; different legacy scopes remain distinct workspaces.

Legacy adoption requires simultaneous authenticated identity and the still-live original in-memory legacy cookie; the backend atomically binds that unclaimed scope, records an event, invalidates the old session and rotates the authenticated session. The client cannot name an arbitrary legacy scope as proof. Missing/expired pre-upgrade cookies cannot recover or infer ownership from filenames, portfolios or content. Orphans remain private under explicit retention. Restore/migration tests must check every original financial hash and foreign key.

## Reviewable stages and evidence gates

1. **A: identity first.** Add additive identity/scope migration, secure account/session/recovery/admin services, owner-compatible auth dependency, workspace adoption, protected account UI, reviewer assignments and RBAC. Before further stages, run actual backend restart/login/retrieve/reproduce for saved risk and optimization, second-user denial, migration fixtures and regressions.
2. **B: credentials/storage.** Authenticated encryption via maintained cryptography/Fernet with external versioned keys; broker authorization remains separate. Add private artifact interface, authorized lifecycle/retention/deletion and stronger parser isolation. Test corruption, key rotation, traversal and index deletion.
3. **C: execution.** Celery with Redis durable delivery plus SQL outbox/job state/leases and idempotent result publication; no exactly-once claim. Persist input references, attempts, deadlines, cancellation and quotas across processes. Use one-slot workers with bounded child computation and crash/retry tests; protect immutable successful publications.
4. **D: deployment.** Separate one-shot migration service, locked non-root images, private service networks/volumes, broker/workers and reverse proxy/TLS. Validate configuration and perform real clean builds/start/restart workflows. No cloud purchases or external/public deployment.
5. **E: operations.** Confidentiality-safe metrics/log correlation, readiness, alerts/runbooks, coordinated encrypted backup manifest and actual disposable restore. Run measured maintained-tool load tests and distributed isolation/quota/crash tests.
6. **F: final validation.** Retain both fixed agent suites, numerical/security/browser regression checks; add scans, image/build/worker/restore CI and optional protected deployment template. Live LLM/independent point-in-time market workflows remain explicit opt-in with accurate unexecuted status when keys/data are absent. Publish readiness categories from actual evidence, never blanket production/institutional claims.

Official implementation references: [pwdlib](https://frankie567.github.io/pwdlib/guide/), [cryptography Fernet](https://cryptography.io/en/latest/fernet/), [Celery task delivery semantics](https://docs.celeryq.dev/en/stable/userguide/tasks.html). Dependencies are added only as each implementation uses them. No order execution, agent shell/SQL/URL tools, numerical UI calculations, automatic champion, arbitrary ownership recovery or paid calls are authorized by this work.
