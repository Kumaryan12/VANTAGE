# Private storage and retention

New PDF originals and ML text/JSON artifacts use a private storage service with server-generated owner/random-object keys, SQL manifests, SHA-256 and exact size verification. Writes use local mode-0600 files, mode-0700 owner directories and atomic no-overwrite publication. Models stage outputs until validated publication; sources must reach ready state before download. Legacy files remain readable through their existing authorized parent manifests without changing scientific artifact hashes. Extracted pages, chunks, embeddings, datasets, input snapshots and numerical results remain owner-scoped database records; binary exports use the same object service. No private files are served through Next public directories or general agent file tools.

`STORAGE_BACKEND=local` uses persistent `MODEL_ARTIFACT_DIR`, `DOCUMENT_STORAGE_DIR` and `PRIVATE_STORAGE_DIR`. The S3 adapter uses an explicit private bucket, default backend credential chain, bounded retries/read sizes, immutable keys, checksums and server-side AES256 encryption. Configure `S3_BUCKET`, `S3_REGION`, optional `S3_ENDPOINT_URL` plus least-privilege service credentials. It does not generate public or presigned URLs. S3 is adapter-tested with a fake client; actual external S3 permissions, lifecycle, versioned deletion and disaster recovery remain unverified. Use a private bucket with public access blocked, TLS, least-privilege object-prefix permissions and a documented version-retention policy.

`GET /api/v1/storage/usage` reports indexed binary objects across all the account's workspaces. Admissions lock the durable principal in SQL and enforce `STORAGE_QUOTA_MB` (default 250 MiB). A separate SQL source/history/snapshot byte quota is also enforced across account workspaces. These counters do not measure all PostgreSQL output/audit rows or legacy files; it must not be described as complete infrastructure disk accounting. Object size is bounded at 12 MiB; PDF uploads at 5 MiB plus a bounded multipart envelope. Legacy model downloads retain checksum verification and authorization.

Saved sources/models are retained until explicit deletion for reproduction. New exports/reports expire after 30 days. Run `python -m app.storage.maintenance retention` to preview a bounded batch; `--apply` erases expired exports/reports and broker ciphertext, sessions expired over 30 days and recovery capabilities expired over one day. Schedule only after selecting the operator's retention policy. Audit records, deletion tombstones and financial sources are not automatically pruned. Unclaimed legacy scopes remain unclaimed; there is no automatic owner inference or automatic orphan erasure. Failed/retried durable jobs clean unpublished staged objects. `python -m app.storage.maintenance reconcile-files` previews unindexed local crash files with a minimum seven-day grace; `--apply` deletes only generated stale unreferenced candidates after a bounded full manifest inventory. Existing referenced and legacy files remain intact. S3 inventory/version reconciliation remains external. Do not bulk-delete directories inferred from names.

Authenticated workspace deletion requires the exact confirmation and an explicit offline-backup acknowledgement. Active jobs block deletion. The workspace is first durably quarantined, then private objects, document indexes, copied evidence, risk/ML/optimization and governance records are erased. Scope/security/deletion identifiers remain as tombstones. A replacement personal workspace is selected. Failure keeps the scope quarantined and supports an owner-authorized retry; it never silently reopens partially deleted data. Other users/workspaces are unaffected. Document-specific deletion also removes retrieval chunks, purges copied document quotes and erases dependent investigation exports. Active investigations/exports block source deletion; active parsing is cancelled and fenced. Export download verifies the current authorized source hash.

Offline/encrypted backups cannot be erased by active-store deletion. Their configured retention, access controls and post-restore deletion reconciliation are separate operational requirements. Do not promise immediate backup erasure. Account identity/audit retention and legal holds require an operator policy; workspace deletion does not delete the identity itself.

PDF parsing runs in a separate bounded subprocess with a stripped environment, isolated temporary input, no inherited application descriptors, 15-second wall/10-second CPU limits, Linux 512-MiB address-space limit, bounded output and page/text/chunk budgets. Linux Landlock restricts reads to the exact input and trusted interpreter dependencies, denies writes; seccomp denies network, subprocess creation/execution, process inspection/signalling and namespace/mount interfaces. `DOCUMENT_SANDBOX_REQUIRED=true` fails closed if kernel confinement cannot be installed. macOS development reports `development_rlimits_only` and does not claim kernel filesystem/network isolation. No reliable table arithmetic or OCR is implemented. Source text remains untrusted data and cannot change agent capabilities.
