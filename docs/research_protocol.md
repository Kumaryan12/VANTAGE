# Phase 3 research protocol, features and governance

## Problem and source integrity

At an observed close t, forecast h(t+1) = E[r(t+1)² | F(t)] under a zero-mean daily approximation. Volatility is sqrt(h), in decimal daily return units. The realized target is the next observed simple return squared: a noisy single-observation proxy, not measured latent variance. There is one non-overlapping daily horizon; no multi-day experiment or inferred next exchange date.

Portfolio returns are aligned adjusted asset returns multiplied by immutable **current snapshot weights**. These are retrospective frozen-weight baskets, not historical account performance. Universe selection, survivorship and absent historical holdings/cash flows remain limitations. Missing asset dates, wrong adjustment, future data, stale current inputs and mixed synthetic/real modes raise errors; no filling or silent intersection. Each prediction records source/frequency/adjustment/data hash, origin/feature-availability date, target interval, training checkpoint, missing-feature count, variance floor and failure details. Origin-close availability is a source assertion, not independently certified publication timing or exchange-calendar completeness.

An optional owner-authorized adjusted benchmark dataset and explicit canonical instrument must have exactly the selected portfolio price dates. Known sectors derive normalized frozen holdings baskets, not broad sector index observations. Market/sector indexes remain unavailable without an appropriate source. Volume is absent from the validated price schema; macro/FX release availability is unverified, so these are excluded. Existing Alpha Vantage imports can supply permitted adjusted history with explicit symbol mappings; FRED/Frankfurter remain context APIs. No paid Kite candle access is assumed.

## Features and preprocessing

`app/ml/features.py` produces origin-close returns and squares at lags 0/1/2/5; trailing 5/10/20/60 second moments and mean returns; EWMA. Full features add absolute return, trailing wealth drawdown, cumulative 20-day return, 5/60 variance ratio and 20-day variation of squared returns. Explicit benchmark context is lagged one observation and adds second moment, rolling correlation and beta. Known-sector baskets add lagged dispersion and mean second moment. Windows are backward-looking; initial 60 observations are warmup. Median imputation is fit separately on each permitted training fold; entirely missing columns are dropped and recorded. No global scaling or future feature selection occurs.

For origin j, label r(j+1)² enters fitting only if j+1 <= current forecast origin. A final-origin forecast is saved separately as unscored, with unknown target date. Leakage tests alter future prices and verify the entire earlier forecast vector is unchanged, alongside lag/boundary and training-only preprocessing tests.

## Models and walk-forward design

- Rolling: mean of the last 20 or 60 squared returns, zero-mean population second moment (no demeaning or ddof adjustment). This differs deliberately from Phase 1 realized sample standard deviation.
- EWMA: initialize with the first 20 squared returns' mean; update lambda*h + (1-lambda)*r². Fixed configurable lambda defaults .94. Rolling estimation resets initialization inside its current history window.
- GARCH: actual ARCH zero-mean Gaussian GARCH(1,1), minimum 150 nonconstant returns, fit using returns times 100. Intercept and forecast variance divide by 10,000; alpha/beta stay dimensionless. Record convergence/near-unit persistence warnings and failed refits; no substitution with another model. Between refits, update the conditional variance using the newly observed return.
- LightGBM: deterministic, single-thread L2 regression on r² times 10,000, direct positive-variance conversion and explicit floor (default 1e-12). No log-target exponentiation or retransformation bias correction is needed. Model misspecification/selection bias still applies. One to three bounded leaf configurations (7/15/31), configurable learning rate, seed, maximum rounds and validation early stopping by QLIKE. Lock the selected configuration and iteration count before test; later refits use only labels observed by their origins.

Defaults: maximum history 1,260 returns, **minimum** initial training 240 (not an exact truncation), preceding validation 60, final test 100, refit every 20 origins, expanding history. Available earlier development observations are retained; rolling estimation bounds training to 252 observations by default. Requirements: history cap 400–5,000; initial minimum 160–2,000; validation 30–252; test 20–500; refit interval 5–126; rolling length 160–2,000 and >= initial minimum. Maximum 25 test refits. The actual history must cover initial+validation+test. Earlier test labels may enter subsequent prequential refits only after observation; tuning and regime thresholds remain frozen. This is explicit online updating, not reuse of future labels.

Each refit records training start/end, maximum label availability, latest training feature origin, config, imputation, fitted parameters and checkpoint hash. The last origin additionally refits for the unscored latest prediction. Expanding and rolling paths are executed in tests. Engineering inspection of this synthetic dataset prevents any claim of a prospectively untouched study.

## Evaluation and risk calibration

All four models use the intersection of valid test targets. Failed forecasts remain null and requested/common/excluded dates and failure counts are explicit. QLIKE = log(h)+RV/h (negative values are valid); MSE/MAE compare **variance**, not standard deviation. The backend also provides 20-target rolling QLIKE within the selected evaluation window, unavailable until 20 consecutive valid predictions. Timings include fitting/prediction and LightGBM validation search; timings are platform-dependent engineering measures.

The Phase 2 `gaussian_risk` calculation receives directly forecast **portfolio** variance, zero mean, weight 1 and fixed saved INR notional. Loss = -V*r; VaR = V*z(confidence)*sqrt(h), at 95% and 99%. A strict loss > VaR is an exception. This does not independently aggregate asset volatility or pretend to estimate a conditional covariance matrix.

Kupiec LR tests unconditional exception probability. Christoffersen uses the n00/n01/n10/n11 first-order transitions; conditional coverage combines the two LR statistics when defined. Zero/all exception likelihoods use stable boundary conventions; undefined independence states remain unavailable. Asymptotic p-values require a configurable minimum (100 default, bounded 50–500); exact binomial p-values are additionally labeled iid descriptive. Low expected exceptions/transitions trigger warnings. Non-rejection proves neither correctness nor superiority. A 100-day 99% test expects only one exception.

Low/medium/high regimes use the origin's trailing 60-day second moment, with 1/3 and 2/3 thresholds estimated before validation. Per-regime errors and coverage use the full saved test window, distinct from the leaderboard's selectable dates. Sparse regime results remain cautious/unavailable as appropriate. No crash prediction is claimed.

Comparison is joint: QLIKE, MSE/MAE, 95/99% coverage, regime stability, complexity, runtime and failures. Paired LightGBM-minus-baseline QLIKE differences have descriptive 500-replicate circular block-bootstrap intervals (block length 10, fixed seed), not a multiple-testing-adjusted significance claim. No automatic champion. Model role changes require a completed evaluation, explicit limitations acknowledgment and written rationale. Champion additionally requires a complete model and at least 100 common observations; this administrative minimum does not establish superiority. Role events and prior-champion demotion are audited per experiment.

## Explanations and artifacts

Final-refit gain/split importance describes that fitted model only. Saved-origin TreeSHAP reloads the exact checksum-verified LightGBM text checkpoint and saved/imputed feature vector, verifies the recorded prediction, and displays bias, contributions, separate floor adjustment and reconstruction residual. One-training-standard-deviation sensitivity can create unrealistic combinations; neither method establishes market causation. Drift uses the **first test refit's** training distribution, never retunes choices and is diagnostic only.

The lightweight registry uses migration 0003: `research_experiments`, `forecast_models`, `research_forecasts`, `model_governance_events`, reusing immutable Phase 2 snapshots/input artifacts. Relational rows contain compact metadata, metrics and manifests; model text/JSON is written atomically under `MODEL_ARTIFACT_DIR` (default repository `artifacts/models`). File path containment, SHA-256, size checks and owner authorization gate retrieval. No pickle or arbitrary model upload/execution. Compose mounts a persistent artifact volume. Back up database and artifacts together; do not delete the volume if evidence must be retained.

A single bounded background executor accepts one job per backend process; busy requests return 503, jobs return 202 and polling status. Workers use separate DB sessions and no broker/provider access. Failures have typed errors; interrupted in-process jobs become `interrupted` when read after restart, without invented completion or automatic resume. This deployment requires **one backend process**. Durable distributed scheduling, quotas and restartable identity are Phase 6 work. Existing ephemeral session ownership means a lost/expired session cannot recover private saved results through the UI, even though rows/artifacts persist; no public deployment claim is made.

## Reproduction and research limits

Run `backend/.venv/bin/python backend/scripts/research_report.py` after migrations. It executes defaults, reloads an artifact/TreeSHAP, reproduces immutable saved inputs, verifies owner isolation, and generates `docs/research/volatility_model_comparison.md`. Use `--smoke` for SQLite/PostgreSQL integration without overwriting the tracked report. Browser experiments remain accessible in their current session; the report script's private synthetic registry records are not attached to a subsequent browser session.

The API reproduces saved data/parameters after hash and model/feature/runtime-version checks, tolerances rtol 1e-8/atol 1e-14 for variance and identical failure masks. Seeds, Python/library versions and git commit when available are recorded. Execution seconds and optimizer/platform details need not match. Runtime `BUILD_COMMIT` can supply an image revision when .git is absent. Reports only contain executed outcomes, with no real-market superiority claim from synthetic data. Larger independently sourced point-in-time datasets and truly independent evaluation are required to answer the economic research question.
