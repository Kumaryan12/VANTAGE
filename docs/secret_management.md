# Secret management

Stage B implements authenticated credential encryption with [cryptography Fernet](https://cryptography.io/en/latest/fernet/). Persistent Kite tokens are private to an authenticated ownership scope, not a browser session. Re-login never renews broker authorization. The provider may revoke or expire a token sooner than the configured conservative 8-hour local lifetime. No order API is added.

Configure `MASTER_KEY_FILE` to an operator-owned, mode-0600 JSON file outside the checkout, e.g. `{ "v1": "<generated-Fernet-key>" }`. Generate a key with `cryptography.fernet.Fernet.generate_key()` in a trusted private provisioning session. `MASTER_KEY_ACTIVE=v1` selects the encrypting version. `MASTER_KEYS` is a development alternative; do not put actual keys in Compose, source, logs, reports or browser variables. The DB contains ciphertext, key version, expiry, revision and owner/provider binding; plaintext is never returned by the metadata endpoint.

Rotation: back up DB/artifacts and separately escrow key recovery material; add a new key alongside the old key, select it as active, restart processes to load configuration, then run `python -m app.storage.maintenance rotate-credential-keys --apply`. Rotation authenticates every row and commits transactionally. Verify usage and backup recovery before removing an old key. Old backups require their corresponding old keys. Corrupt ciphertext, swapped ownership/metadata or missing keys fail closed with a typed error. Lost keys require broker re-authorization; there is no bypass or plaintext fallback.

Local credential revocation clears active ciphertext and records an audit event. It does not assert that remote broker revocation succeeded or erase older backups. The retention command clears expired credentials. Broker tokens are not identity credentials and never enter agent tool facts or provider prompts. Legacy anonymous local mode retains its explicitly ephemeral in-memory broker behavior; production must require durable authentication.

LLM/market-provider credentials and database connection secrets remain backend deployment configuration. Use an external secret manager or mounted secret files in deployment; do not persist unused per-user API keys or send them to LLMs. This local implementation is not managed KMS/envelope encryption. Operator, host and separately held key security remain trust boundaries. Actual external secret-manager recovery is not verified.
