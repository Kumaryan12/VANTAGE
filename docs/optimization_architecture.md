# Optimization architecture

Phase 5 extends the existing read-only service; it does not add execution or replace Phase 2 mathematics.

`contracts.py` validates policy/objective/cost/solver/study requests. `data.py` authorizes approved history through `risk/service`, captures immutable dated inputs and builds the ordered covariance dataset. `solver.py` contains pure CVXPY construction and independent NumPy checks. `comparison.py` delegates tails, Gaussian simulation and Euler attribution to Phase 2. `studies.py` explicitly enumerates bounded settings. `counterfactual.py` delegates identical hypothetical/historical scenarios to Phase 2 and saves/replays scenario inputs. `service.py` owns jobs, result hashing, reproduction and candidate registration. Thin API handlers authenticate the existing browser session and call these services.

Migration 0006 adds explicit new agent tool-call sequence; legacy sequence remains unknown/null. Migration 0007 adds `optimization_runs` and `optimization_counterfactuals`. Each run owns compact policy/solution/comparison/study JSON plus immutable existing portfolio-snapshot/history-artifact references, input/result/covariance hashes, dates and runtime/model versions. This normalized run aggregate avoids separate tables duplicating each study point or constraint. No simulation draw matrix is persisted. Migration 0008 adds `governance_models` and append-only review events, owner/source uniqueness and source/version/evidence lineage. Original migrations and endpoints remain compatible.

The optimization queue has one worker and one active-job semaphore; overload returns 503. It validates all planned windows/universes before enqueueing. Frontier/studies are limited to eight variants (sensitivity includes its base); max 50 holdings; simulation count 2,000–10,000 per comparison; solver max 10 seconds/1,000 iterations; study budget 90 seconds checked between bounded points. Parameter validation and necessary checks can reject earlier. Failure cannot publish a stale feasible proposal. Futures retain at most 64 completed references. There is no distributed scheduling, durable retry or production-wide quota. A foreign/stale runner leaves interrupted evidence, not a claimed completion.

Reproduction verifies owner scope, result/snapshot/artifact/parameter hashes, ordered covariance hashes, model version and recorded Python/NumPy/Pandas/CVXPY/CLARABEL runtime. It rehydrates saved prices and portfolio without provider access. Weights use rtol `1e-6`, atol `1e-7`; annual variance rtol `1e-7`, atol `1e-10`; risk metrics rtol `1e-6`, INR atol `.01`. Status/missingness and covariance hashes must match. Timings and newly assigned IDs are excluded. Singular matrices can legitimately have nonunique optima, so a weight mismatch remains visible even if objective values agree.

Saved comparisons accept 2–4 distinct feasible single runs on identical actual point-level economic data, as-of/notional, current weights, sectors, covariance hash, confidence, seed and simulation count. Different retrieval timestamps remain recorded but are not an economic mismatch. Differing covariance/windows require a labeled sensitivity study, not a like-for-like ranking.

Counterfactual records hash their results and version, original optimization input hash, point, immutable scenario artifact and exact scenario parameters. Retrieval and replay verify all ownership and hashes. Explicit scenario-history datasets may supply older covered observations; replay reuses the saved artifact without refetching.

`agent/optimization_tools.py` adds eight strict read/calculation tools. An executed run is pinned into subsequent tool requests so concurrent UI work cannot substitute a different latest result. The backend computes actual risk reduction and requested-goal status; pure minimum-variance optimality is distinguished from a merely feasible penalized result. Existing final fact/unit/date/hash verification applies. Provider calls have no governance write capability. The Next.js laboratory formats and charts backend outputs only.

Private rows and artifacts retain the existing ephemeral session ownership (12 hours, invalid after process restart). Storage has no automatic retention/recovery guarantees. Preserve DB/artifact volumes together. Phase 6 covers persistent identity, backups/retention, workers, hardened operations and production deployment. No investment-performance or institutional-readiness claim follows from this architecture.
