# Durable job processing

Phase 6 Stage C uses [Celery](https://docs.celeryq.dev/en/stable/userguide/tasks.html) with Redis delivery and PostgreSQL as the authoritative job/outbox/state store. Broker messages contain only opaque job IDs. Workers load captured authorized inputs from SQL and private storage; no arbitrary callable, SQL, shell, URL or model-selected capability is accepted. Celery accepts JSON only, uses late acknowledgements, rejects lost-worker tasks, prefetches one, disables remote control and limits process lifetime/memory recycling. Redis result payloads are not used as financial evidence. Redis must be private and persistent; PostgreSQL outbox re-dispatch also recovers missing delivery.

`JOB_BACKEND=local` retains explicitly local development executors and existing APIs. `JOB_BACKEND=celery` atomically saves the resource plus SQL job in one transaction. The API does not need a healthy broker to acknowledge durable queued work. Run `python -m app.jobs.dispatcher` continuously, plus separate Celery workers. Dispatcher outages leave visible queued work, never fabricated completion. PostgreSQL is required for distributed production operation; SQLite is a development fallback.

```bash
python -m app.jobs.dispatcher
celery -A app.jobs.celery_app:app worker -Q research,optimization,document,risk,report --concurrency=2 --pool=prefork
celery -A app.jobs.celery_app:app worker -Q agent --concurrency=1 --pool=prefork
celery -A app.jobs.celery_app:app worker -Q evaluation --concurrency=1 --pool=prefork
```

Use distinct worker names when starting multiple workers. Dedicated orchestration queues avoid deadlocking an agent/evaluation waiting for its child numerical/document job. macOS local smoke uses Celery solo because prefork failed in the actual macOS environment; Linux deployment/CI uses prefork. Do not describe the macOS run as Linux process-pool verification.

## State, leases and publication

Each job records scope/principal, type, captured input reference/hash, idempotency key, created/available/start/finish times, attempt history, timeout, worker identity, random fencing token, expiring lease, failure category and result reference/hash. States include queued, running, completed, failed, cancel_requested, cancelled, interrupted and retrying. Per-kind time budgets are research 240s, optimization 110s, document 90s, agent 120s (its internal request budget remains at most 90s), evaluation 900s, risk 90s and report 60s. Celery soft/hard limits and a worker watchdog bound uncooperative work; container resource limits are a separate deployment gate.

Claiming is serialized and verifies captured references against the authorized immutable source. Duplicates cannot claim a running/successful job. A heartbeat cannot revive an expired lease. **Every worker SQL commit**, including intermediate trace/progress and tool-thread writes, checks the current token, lease, cancellation and active scope under a row lock. Successful numerical/document/answer outputs and completed job state are committed together. Lost/stale/cancelled workers cannot publish a late success. At-least-once execution is intended; exactly-once computation is not claimed. A provider may have performed work before a crash even if no answer was published.

Expired leases are recorded as interrupted and retried with bounded exponential backoff, up to three attempts for provider-free numerical/document/report work. Agents/evaluations and semantic-document work do not automatically repeat after a crash; the owner can explicitly request an eligible retry, below three attempts. Ordinary validation/execution failures remain failed until explicit retry. Retry uses original inputs and cannot overwrite successful or cancelled outputs. Incomplete staged files are removed on failure/retry when storage is available; failure leaves a cleanup diagnostic. Old unindexed local crash files have a dry-run-first reconciliation command with a minimum seven-day grace. Failed trace evidence is retained until retry resets that attempt; successful prior allocations are never substituted for failed agent work.

Original numerical API shapes remain compatible. New `GET /api/v1/jobs`, `GET /{id}`, `POST /{id}/cancel` and `POST /{id}/retry` authorize the active workspace. `POST /risk` captures portfolio/adjusted history for provider-free simulation; optional request keys bind to sealed input, and a conflicting input returns 409. `POST /report` exports an authorized completed risk/optimization/investigation source to a checksum-verified private JSON artifact. Background Jobs shows queue/attempt/failure/cancel/retry status and private export downloads. Configured execution is not a claim that a worker is currently healthy.

## Distributed resource controls

SQL admission serializes a bounded global queue (100 by default), per-account active work across scopes (4), and one queued/running job per account/type. Global running limits are research/evaluation/report 1 and optimization/document/agent/risk 2 each. Dedicated queues, one-at-a-time prefetch, per-account admission and hard time budgets limit starvation; no weighted enterprise scheduler is claimed. Queued work expires after 24 hours. `operation_gates.jobs.paused` suspends new background admission/claiming for maintenance.

Legacy synchronous risk/stress/replay paths keep numerical behavior and add a PostgreSQL session advisory slot deployment-wide in durable mode. Process/connection loss releases it. A busy slot returns a clear error; larger simulations can use the durable endpoint. Broker/market/FX/macro and LLM/embedding reservations use atomic SQL counters across instances. Each logical provider call reserves two possible attempts, max 120 deployment-wide and 30 per account per minute. LLM/embedding calls conservatively reserve one million token units per turn/batch from `PROVIDER_DAILY_RESERVED_TOKENS` (default ten million); these are deliberately conservative reservations, **not measured/billed tokens or broker quotes**. Existing per-investigation actual token/step/time limits and recorded provider usage remain. No paid calls are run by mandatory tests.

Binary objects share the account's configured quota. SQL-backed histories, immutable price inputs and portfolio snapshots share a separate `SOURCE_QUOTA_MB` bound, default 250 MiB. Those limits do not measure all SQL output/index/audit rows, old unindexed files, S3 versions or physical database/host disk consumption. Existing per-upload/page/chunk/refit/draw/solver limits remain; monitor infrastructure storage and select retention rather than describing these application counters as a complete filesystem quota.

The worker checks numerical library/Python compatibility before execution and records actual runtime evidence. Completed ML/optimization records use the actual worker runtime, preserving the existing reproduction tolerances and covariance diagnostics. Financial model versions and the original Phase 3–5 measured reports are unchanged.

## Executed evidence

`backend/scripts/worker_smoke.py` requires migrated disposable PostgreSQL and Redis. It starts two API processes, dispatcher and actual Celery workers, kills a claimed research worker, recovers on attempt two, cancels another live job with no models published, executes all seven task adapters (including the unchanged 60-case evaluation), denies a second user, restarts the API, retrieves saved ML/PDF/investigation/risk/optimization/export outputs and reproduces risk/optimization. The local macOS solo run passed with all 60 durable evaluation cases passing. Linux prefork evidence is a separate CI/container gate. Unit tests independently exercise stale-token and cancel publication fencing, duplicate success immutability, corrupted inputs, broker outage/outbox retry, cross-workspace quotas, provider reservations, source quotas, expired heartbeat rejection and crash-file reconciliation.
