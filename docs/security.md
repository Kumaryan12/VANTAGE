# Security boundary

Local single-user read-only analysis. No order, GTT, execution, arbitrary URL fetch or shell endpoints. Phase 4 adds only bounded authorized investigation/provider interfaces.

Kite API secret and access tokens stay on the backend. A cryptographically random, HttpOnly, SameSite=Lax cookie identifies an in-memory expiring session. Tokens are never placed in the cookie, database, frontend bundle, browser storage, or logs. OAuth-style login uses a single-use random state bound to the initiating browser session with a ten-minute expiry. Callback uses Kite `redirect_params`; failure requires a fresh login. Session expires within 12 hours and Kite can invalidate earlier; invalid token responses clear local broker access. Logout invalidates the remote token before discarding it where possible, and always clears local access. Restart invalidates all sessions; run one backend worker.

Same-origin mutation checks reject unexpected Origin headers; browser fetch-metadata checks reject cross-site mutations. CORS is not opened. Next.js proxies only to configured backend; all provider hosts are hardcoded HTTPS. Query strings and upstream exception strings are never logged, including the token-bearing callback. Sensitive responses use no-store and a restrictive referrer policy. Uploads have byte/row/instrument limits and are validated from bounded bytes; multipart handling may use a temporary spool file. No user-controlled filesystem paths are accepted. Session ownership is enforced for history selection. Expired session datasets are orphaned until manual retention cleanup (not exposed to subsequent users).

Configure COOKIE_SECURE=true behind HTTPS. Keep DATABASE_URL, KITE_API_SECRET, ALPHA_VANTAGE_API_KEY, and FRED_API_KEY out of source control. Do not expose this app publicly until identity, durable encrypted sessions, quotas, retention, TLS, and audit access controls have been added. PostgreSQL records contain private historical imports; protect the volume and backups.

Kite account credentials are entered only on Zerodha's official website. The UI only receives an opaque session and read-only authorized result data. Account positions/margin snapshots must be treated as private. Provider errors return generic typed messages; raw payloads and URLs containing keys must never be returned.


Phase 2 persists private holdings snapshots and selected dated histories so runs can be replayed. These records, their compact results and provenance are session-owned; retrieval, comparison and replay verify ownership before returning data. Tokens remain memory-only and are never persisted in these records. Input hashes detect changed snapshots, artifacts or model parameters before replay. No arbitrary model code or user-provided covariance/exposure script is accepted. Request bounds and a single-calculation semaphore cap simulation work. Durable identity/retention recovery after session expiry or restart remains unimplemented; database persistence must not be mistaken for durable authentication.

## Phase 3 model evidence

Research jobs/models/forecasts/reports/artifact ZIPs use the existing opaque session owner. No model uploads, pickle loading, brokerage orders or LLM tools are introduced. Immutable input hashes and text/JSON checkpoint path containment/SHA-256 checks protect reproduction; artifacts live outside DB rows and public static files. Mutation origin checks apply to training and governance. One bounded worker and bounded histories/search/refits limit local work; multi-user quotas and distributed scheduling remain unimplemented. Ephemeral sessions cannot recover private records after lost/expired identity; persistent rows/artifacts require future retention/backup policy. See research_protocol.md.


## Phase 4 investigation boundary

Every analytical tool and persisted investigation/document/evaluation is session-scoped; documents are filtered before keyword/vector retrieval. Intent-specific allowlists, strict schemas, server-bound account/data context, deterministic numerical/citation checks and sealed evidence constrain provider outputs. No LLM can change holdings/governance or execute orders, SQL, shell or arbitrary network requests. Document text is untrusted evidence and cannot grant permissions.

Provider keys stay backend-only. Live AI and external embeddings require explicit consent; relevant redacted facts/passages are minimized, raw prompts/private reasoning are not persisted, and `store:false` is requested. Redaction is not complete DLP and provider retention policies still apply. PDF originals/chunks are private plaintext research data. Fixed parser subprocess/resource limits, active-content rejection and attachment downloads reduce risk but are not a hardened OS sandbox or malware scanner.

Per-session request quotas and execution budgets suit local research, not adversarial public traffic. Single-process ephemeral identity, orphaned records, incomplete retention/forensic deletion and backup operations remain Phase 6 work. Database and PDF/model artifact volumes must be protected together. See [agent_threat_model.md](agent_threat_model.md) for residual risks and [agent_architecture.md](agent_architecture.md) for cancellation/restart semantics.

## Phase 5 decision support and review

All optimization, comparison, scenario, reproduction and governance routes bind ownership to the existing HttpOnly browser session. Cross-owner sources return 404; mutation retains same-origin checks. No client-supplied owner proves access. Strict schemas reject unknown/unheld assets, injected policy fields and invalid numerical data; actual holdings never use synthetic fallback. Work is bounded by single-process queue/point/solver budgets. History and immutable snapshots/results are private, hash-checked and excluded from logs/commits. Scenario replay checks result/version/input/artifact hashes. Readiness checks all new schema tables and explicit tool sequence.

Optimization tools have no model-controlled policy arguments and stop without substituting stale successful allocations on failure. Actual created runs are pinned to subsequent tools. Expected returns need user-provided sourced vectors; goal achievement is computed deterministically from matched risk results. Eight new tools do not expose SQL, shell, URLs, broker/order operations, governance writes or arbitrary artifact paths. Human review requires owned source evidence, actual reproduction, rationale, explicit acknowledgements and eight assessment areas; every approval is methodology_research only. A session token is not durable reviewer identity or enterprise maker-checker. Prior limitations on credentials, recovery, parser isolation, retention and deployment remain Phase 6. See [governance](model_governance.md) and [optimization architecture](optimization_architecture.md).
